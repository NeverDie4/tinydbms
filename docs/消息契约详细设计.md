# tinydbms 消息契约详细设计

本文是字段级消息契约的主体设计，包含初版生命周期与边界约束；生成公共头文件前仍需与各模块实现核对一次。后续字段调整需要重新确认。

崩溃恢复、显式 flush API 与逐操作 fsync 不在本文范围；正常 close_storage 时的统一落盘属于初版范围。
未来日志条目统一命名为 `LogEntry`，不与行记录 `Record` 混淆。
初版单进程、单线程、顺序执行，不实现事务与并发控制；未来若引入，控制逻辑归 core 执行层，storage 只补充必要的原子性边界。

下文代码块表达逻辑形态与字段，按主题分组展示；不保证按出现顺序可直接编译，实现头文件时自行处理前置声明与定义顺序。

## 1. 基础类型与元数据

### ID

```cpp
using TableId = std::uint32_t;   // 由 core 的 Catalog 分配
using ColumnId = std::uint32_t;  // 等于建表列序 0..n-1，不单独分配
```

TableId 使用 `0..UINT32_MAX` 全部取值，0 合法且无保留含义；空库的第一个 TableId 为 0。

### Type 与 Value

```cpp
inline constexpr std::uint32_t kMaxVarcharBytes = 1024;      // 单个 VARCHAR 值的 UTF-8 字节上限
inline constexpr std::uint32_t kMaxRowLogicalBytes = 4096;   // 单行逻辑载荷字节上限

enum class Type {
    kInt32,
    kInt64,
    kFloat,
    kDouble,
    kBool,
    kVarchar
};

struct Value {
    std::variant<std::int32_t, std::int64_t, float, double, bool, std::string> data;
};
```

`Type` 与 `Value` 的 variant alternative 一一对应。初版 SQL Core 类型为 `INT32`、`VARCHAR`；
`INT64`、`FLOAT`、`DOUBLE`、`BOOL` 是允许由 Catalog/Storage 持久化的 Extended 类型。Compiler 后续负责 SQL
类型字面量、推导和用户可见错误；Storage 仍须对 API 输入独立执行列类型校验。
Value 只表示可存储值，是共享类型。比较/逻辑运算的中间结果由 core 执行器内部处理；BOOL 也允许作为持久化列类型。
NULL 为后期可选，初版不支持。
VARCHAR 值必须是合法 UTF-8，长度按 UTF-8 字节数（即 `std::string::size()`）计算；compiler 在解析字符串字面量时校验。
单行逻辑载荷 = 各列逻辑长度之和：INT32/FLOAT 计 4 字节，INT64/DOUBLE 计 8 字节，BOOL 计 1 字节，VARCHAR 计其 UTF-8 字节长度；该公式与 storage 的物理编码格式无关。
`kMaxVarcharBytes` 与 `kMaxRowLogicalBytes` 是共享上限，storage 做最终校验，超限返回 `kValueTooLarge`。
后续 Record Serialization 必须使用显式、稳定的物理编码，禁止直接写入 C++ 对象内存布局：INT32 4 bytes、INT64 8 bytes、FLOAT 4 bytes、DOUBLE 8 bytes、BOOL 1 byte、VARCHAR 为显式长度加 UTF-8 bytes。本阶段不实现该编码。

### 表与列元数据

```cpp
struct ColumnMeta {
    std::string name;
    Type type;
};

struct TableMeta {
    TableId table_id;
    std::string table_name;
    std::vector<ColumnMeta> columns;  // 顺序即记录布局
};
```

ColumnId 等于列序，不需要额外存储；ALTER TABLE 不纳入，未来需要时再设计映射层。

## 2. CatalogView

```cpp
struct CatalogView {
    // 借用 core Catalog 中的表元数据数组，编译调用期间有效
    std::span<const TableMeta> tables;
};
```

compiler 通过线性查找表名或 TableId 获取结构。CatalogView 由 core 保证在调用期间有效，compiler 不持有、不修改。

## 3. SQL 初版语义边界

这部分定义跨模块必须一致的语义规则；具体文法与 parser 结构由 compiler 负责人决定。

### 支持的语句

- `CREATE TABLE`
- `INSERT INTO ... VALUES`
- `SELECT ... FROM ... [WHERE ...]`
- `DELETE FROM ... [WHERE ...]`
- SELECT 初版仅单表查询，无 JOIN、聚合、GROUP BY/ORDER BY、DISTINCT、子查询与列别名。
- 初版不支持 UPDATE、DROP、SHOW、ALTER，也不支持主键、唯一、默认值、外键、索引等列约束。
- 初版每条语句必须以 `;` 结束；没有“末条可省略分号”的例外。

### 标识符

- 关键字大小写不敏感。
- 表名、列名大小写不敏感，统一规范化为小写。
- 标识符为 ASCII：`[A-Za-z][A-Za-z0-9_]*`，长度 1..64；
  compiler 统一转为小写后，消息层与 Catalog 保存 `[a-z][a-z0-9_]*` 形式。
- SQL 关键字、重复表名/列名等语义检查由 compiler 负责；storage 在 create_table 消息层独立校验名称语法与唯一性，避免两侧标准不一致。

### 类型与表达式

- Core SQL 的 INT32 与 VARCHAR 之间不做隐式转换。
- INT32 支持 `= != < <= > >=`；VARCHAR 只支持 `=` 与 `!=`。Extended 类型的 SQL 推导规则由后续 compiler 阶段补充，不改变 Storage 的类型校验责任。
- VARCHAR 值必须为合法 UTF-8，长度按 UTF-8 字节数计；单个值超过 `kMaxVarcharBytes` 由 compiler 或 storage 报错。
- 支持 AND、OR、NOT；操作数是比较结果，比较结果是内部 BOOL，不进入 Value。
- 初版不包含算术表达式。
- INSERT 的 VALUES 只允许字面量；初版 SQL 整数字面量面向 INT32，字符串面向 VARCHAR。
- INSERT 若提供列清单，必须是该表的全列，可改变顺序；省略列清单等于按建表列序全部插入。
  初版没有默认值与 NULL，不支持只插入部分列。

## 4. 可执行入口 ↔ core

### 产品行为

- 一个可执行文件，默认交互式 REPL，支持 stdin 批处理。
- stdin 连接到交互终端时进入 REPL；stdin 非交互时按整段批处理执行。
- REPL 以 EOF 退出（Unix 终端通常 Ctrl-D；Windows 控制台通常 Ctrl-Z 后回车），初版不提供 SQL 之外的元命令。
- 入口支持可选 `--data-dir <DIR>`，缺省使用当前目录下的 `tinydbms-data/`；该参数只用于打开数据库，不涉及 SQL 解析。
- 入口只负责读入文本、把文本交给 core、逐条展示 core 返回的结果与错误。
- 入口不拆句、不解析 SQL、不包含业务逻辑。

### REPL 的输入边界

初版交互模式按“行”提交：用户输入一行并回车后，该行作为一段文本交给 core。
一行内可以包含多条完整语句；跨行 SQL 暂不支持，列为后期优先升级项。
升级跨行时不能直接复用当前 split 接口；需要把协议扩展为返回完整语句、pending 文本与完整性状态
（例如 `SplitResult { statements, pending, need_more }`），由 core 持有缓冲，入口不自行解析 SQL。

### 消息与函数

```cpp
struct OpenDatabaseRequest {
    std::string data_dir;   // 数据库目录，UTF-8 编码；缺省 ./tinydbms-data
};

struct OpenDatabaseResult {
    std::optional<Error> error;
};

struct CloseDatabaseRequest {};

struct CloseDatabaseResult {
    std::optional<Error> error;
};

struct ExecuteScriptRequest {
    std::string text;   // REPL 一行，或 stdin 批处理的整段文本
};

struct ExecuteScriptResult {
    // 每条已尝试语句一个结果；遇到错误后停止，剩余语句不执行
    std::vector<ExecuteResult> outcomes;
};

OpenDatabaseResult  open_database(const OpenDatabaseRequest&);
CloseDatabaseResult close_database(const CloseDatabaseRequest&);
ExecuteScriptResult execute_script(const ExecuteScriptRequest& request);
```

行为约定：

- 入口启动时先 open_database，正常退出前 close_database；execute_script 只在数据库打开后调用。
- open_database 内部负责 storage 的 open 与 Catalog 恢复；close_database 负责 storage 的关闭与落盘收尾。
- 未打开数据库、重复打开或重复关闭等非法生命周期调用由 core 返回 Error。
- 空文本或只由完整注释组成的文本返回空 outcomes；未闭合字符串/块注释会作为语句返回并产生编译错误。
- core 先调用 compiler 的 `split_statements`，再逐条“编译 → 执行”。
- CompileError.location 相对单条语句；core 结合该语句的 start 换算为整段输入绝对位置后再对外返回。
- 某条语句以 Error 结束（独立 Error，或 CommandResult 携带 error）时立即停止，该错误是 outcomes 最后一项的一部分。
- INSERT/DELETE 在执行中发生 storage 错误且已有部分行成功时，core 返回携带 error 的 CommandResult；
  无部分副作用可报告时，直接返回 Error。
- SELECT 扫描中发生 storage 错误时丢弃已收集的行，直接返回 Error，不再产生部分 QueryResult。
- DDL 成功执行后 core 立即更新 Catalog，再处理下一条语句。

## 5. core ↔ compiler 消息

### SourceLocation

```cpp
struct SourceLocation {
    int line;    // 从 1 开始
    int column;  // 从 1 开始
};
```

SourceLocation 在契约中有三种语义：

- `SplitStatement.start`：语句首字符在整段输入中的绝对位置；
- `CompileError.location`：错误在单条语句文本中的相对位置；
- 用户可见 `Error.location`：core 换算后的整段输入绝对位置。

行列计数规则：

- 行按 `\n` 分割，从 1 开始；`\r\n` 视为一个换行，`\r` 不占列；
- 列按 UTF-8 字节计数，从 1 开始。

### 分句：split_statements

compiler 模块对外暴露无状态纯函数：

```cpp
struct SplitStatement {
    std::string sql;       // 一条语句文本，保留原文中从 start 到自身结尾分号的内容
    SourceLocation start;  // sql 首字符在整段输入中的绝对位置（1-based）
};

// 输入整段 SQL 文本，返回带起点的语句列表；列表顺序即原文顺序
std::vector<SplitStatement> split_statements(std::string_view text);
```

语义约定：

- 识别字符串（含 `''` 转义）、`--` 单行注释、`/* */` 块注释，以及作为语句分隔符的 `;`。
- 每条返回的 `sql` 保留从 `start` 到自身结尾分号的原始前导空白与注释；
  compile 只接收 `sql` 并报告相对位置，core 结合 `start` 换算绝对位置。
- 空输入返回空列表；仅由空白和“完整注释”（`--` 至行尾或 EOF、闭合的 `/* */`）组成的输入返回空列表。
- 只含空白与完整注释的分段不返回，连续分号之间的空语句同样被跳过。
- 未闭合字符串或块注释视为残缺语句，必须返回给 compile 报词法错误；
  此规则优先于上面的“纯注释丢弃”，不能把 `/* unfinished` 按纯注释吞掉。
- 最后一段没有分号的非空文本也作为一条语句返回；初版统一要求语句以分号结束，
  由 compile 报告缺少分号（语法错误）。
- 返回列表的顺序即原文顺序，`vector.size()` 就是语句数量，不需要额外计数字段。

拆出的语句列表由 core 持有，compiler 调用完即忘，不保存任何状态。

### 相对坐标换算

core 把 `CompileError.location`（相对 sql）换算为整段输入绝对位置：

```text
绝对行号 = start.line + 相对行号 - 1

绝对列号 =
    相对行号 == 1 时：start.column + 相对列号 - 1
    相对行号 > 1 时：相对列号
```

## 6. LogicalPlan

compiler 负责编译期：解析、类型检查、生成 Plan 与 Expr。
core 负责运行期：对 storage 返回的记录求值比较、AND/OR/NOT。
storage 不参与表达式。

### 顶层 Plan

```cpp
struct Plan {
    std::variant<
        CreateTablePlan,
        InsertPlan,
        DeletePlan,
        QueryPlan
    > kind;
};
```

### CreateTablePlan

```cpp
struct CreateTablePlan {
    std::string table_name;          // 尚无 ID，执行时由 core 分配
    std::vector<ColumnMeta> columns;
};
```

### InsertPlan

```cpp
struct InsertPlan {
    TableId table_id;
    std::vector<ColumnId> columns;   // 空 = 全列按建表列序；非空 = 全列的重排，缺列由 compiler 判为语义错误
    std::vector<std::vector<Value>> rows;  // VALUES 多行
};
```

rows 中每一行的值顺序与 columns 一致；columns 为空时与建表列序一致。
core 执行时先把列清单重排展开为建表列序的全行，再交给 storage。

### DeletePlan

```cpp
struct DeletePlan {
    TableId table_id;
    std::optional<Expr> predicate;   // nullopt = 无 WHERE，删除全部
};
```

### QueryPlan 与算子树

```cpp
struct QueryPlan {
    std::unique_ptr<PlanNode> root;
};

struct SeqScanNode {
    TableId table_id;
};

struct FilterNode {
    Expr predicate;
    std::unique_ptr<PlanNode> child;
};

struct ProjectNode {
    std::vector<ColumnId> outputs;   // SELECT 列表，* 已由 compiler 展开
    std::unique_ptr<PlanNode> child;
};

struct PlanNode {
    std::variant<SeqScanNode, FilterNode, ProjectNode> kind;
};
```

结果列名由 core 根据 ColumnId 与查询表的 TableId 查 Catalog 得到，不在 Plan 中重复携带。

### Expr

```cpp
struct Expr {
    std::variant<
        ColumnRef,
        Literal,
        Binary,
        Unary
    > kind;
};

struct ColumnRef {
    ColumnId column_id;
};

struct Literal {
    Value value;
};

struct Binary {
    std::variant<CmpOp, LogicOp> op;
    std::unique_ptr<Expr> lhs;
    std::unique_ptr<Expr> rhs;
};

struct Unary {
    UnaryOp op;   // 初版仅 NOT
    std::unique_ptr<Expr> operand;
};

enum class CmpOp {
    kEq, kNe, kLt, kLe, kGt, kGe
};

enum class LogicOp {
    kAnd, kOr
};

enum class UnaryOp {
    kNot
};
```

初版不包含算术表达式。Expr 的 C++ 落地需要递归包装类型，本文只规定逻辑形态。

## 7. core 内部行与用户输出

命名约定：

- `Record` 只用于 storage 边界：RecordId + 全行列值。
- core 执行器内部处理的行叫 `Row`。
- `RecordId` 由 storage 分配，对 core 不透明。

```cpp
using Row = std::vector<Value>;   // core 执行器内部与结果中的行

struct ColumnHeader {
    std::string name;
    Type type;
};

struct QueryResult {
    std::vector<ColumnHeader> columns;
    std::vector<Row> rows;
};

enum class ErrorKind {
    kCompile,
    kExecute,
    kStorage,
    kInternal
};

struct Error {
    ErrorKind kind;
    // 仅编译错误携带；已由 core 换算为整段输入的绝对位置
    std::optional<SourceLocation> location;
    std::string message;
};

struct CommandResult {
    std::uint64_t affected_rows;   // CREATE 成功时为 0
    // 仅 INSERT/DELETE 部分行成功后 storage 出错时携带；
    // 此时 affected_rows 是错误前已成功执行的行数，core 停止后续语句
    std::optional<Error> error;
};

struct ExecuteResult {
    std::variant<QueryResult, CommandResult, Error> outcome;
};
```

## 8. core ↔ storage 消息

### 生命周期

```cpp
struct OpenStorageRequest {
    std::string data_dir;   // 数据库目录，UTF-8 编码；来自入口 --data-dir 或缺省 ./tinydbms-data
};

struct OpenStorageResult {
    std::optional<StorageError> error;
};

struct CloseStorageResult {
    std::optional<StorageError> error;
};
```

生命周期语义：

- core 的 open_database 调用 open_storage，成功后才能调用其他 storage API；失败时 core 中止启动。
- core 的 close_database 调用 close_storage，正常退出前必须执行。
- 成功返回表示操作已更新 storage 内部状态；正常 close_storage 后重启可见。
- data_dir 不存在时由 open_storage 创建目录；创建失败返回 `kIoError`。
- data_dir 存在但不是目录或不可访问时返回 `kIoError`。
- data_dir 为空视为新建数据库；目录非空但缺少或无法识别 storage 元数据时返回 `kCorrupt`，不得覆盖已有文件。
- open_storage 成功后，若后续 list_tables/Catalog 恢复失败，core 先调用 close_storage 清理，再中止启动；清理错误不覆盖主错误。
- data_dir 统一使用 UTF-8 字符串；Windows 入口负责把宽字符路径参数转换为 UTF-8，storage 内部再转换回原生路径。
- 初版不承诺逐次 fsync、进程崩溃或断电后的持久性；这些属于范围外的显式 flush 与崩溃恢复议题。

### 写入与删除

```cpp
struct InsertRequest {
    TableId table_id;
    std::vector<std::vector<Value>> rows;   // 一次多行，按顺序执行
                                            // 每行都是“全行、按建表列序”，由 core 在调用前展开

    std::vector<RecordId> record_ids;       // 与已成功插入的行一一对应
    std::optional<StorageError> error;

    TableId table_id;
    std::vector<RecordId> record_ids;       // 一次一串，按顺序执行
};

    std::uint64_t deleted_count;            // 已成功删除的数量
    std::optional<StorageError> error;
};
```

### StorageError

```cpp
enum class StorageErrorKind {
    kTableNotFound,
    kCursorInvalid,
    kValueTooLarge,
    kIoError,
    kCorrupt,
    kInvalidRequest
};

struct StorageError {
    StorageErrorKind kind;
    std::string message;
};
```

### Result 不变量

- error 为空表示成功；error 非空表示操作在错误处停止。
- ListTablesResult：error 为空时 tables 是 storage 当前已持久化的全部表；error 非空时 tables 无效，core 应中止启动恢复。
- CreateTableResult：错误时不得留下可被 list_tables 看到的半成品表；core 不更新 Catalog。
- OpenTableResult：error 为空时 cursor_id 必有值；错误时 cursor_id 为空。
- ScanNextResult：record 有值 = 成功返回一行；record 空且 error 空 = 扫描结束；error 非空时 record 无效。
- InsertResult：成功时 `record_ids.size() == rows.size()`；错误时 `record_ids` 只包含错误前已成功插入的行。
- DeleteResult：成功时 `deleted_count == record_ids.size()`；错误时 `deleted_count` 是错误前已成功删除的数量。
- 游标无论正常结束还是出错中断，core 都应调用 close_cursor。
- storage 对请求做基本校验：操作不存在的表返回 `kTableNotFound`；非法或已关闭的 cursor 返回 `kCursorInvalid`；
  INSERT 的行列数、列类型或逻辑载荷上限不符返回 `kInvalidRequest`/`kValueTooLarge`；
  create_table 的 table_name/列名不符合 `[a-z][a-z0-9_]*` 且长度不在 1..64、列清单为空或列名重复返回 `kInvalidRequest`；
  create_table 使用与已有表重复的 TableId 或 table_name 返回 `kInvalidRequest`；
  delete_records 收到不属于该表或已失效的 RecordId 返回 `kInvalidRequest`。
- 错误优先级：同一语句先出现的错误优先；
  扫描已出错时 close_cursor 的后续错误不覆盖；
  扫描正常结束但 close_cursor 失败时，SELECT 丢弃已收集行并返回该错误，DELETE 中止且不执行删除。

### API

```cpp
OpenStorageResult open_storage(const OpenStorageRequest&);
CloseStorageResult close_storage();
ListTablesResult  list_tables();
CreateTableResult create_table(const CreateTableRequest&);
OpenTableResult   open_table(const OpenTableRequest&);
ScanNextResult    scan_next(CursorId cursor_id);
std::optional<StorageError> close_cursor(CursorId cursor_id);
InsertResult      insert(const InsertRequest&);
DeleteResult      delete_records(const DeleteRequest&);   // 避开 C++ delete 关键字
```

## 9. 典型时序

### 启动

```text
入口解析 --data-dir → core.open_database(data_dir)
core → open_storage(data_dir) → storage
open_storage 失败 → 中止启动
core → list_tables → storage
list_tables 失败 → core → close_storage 清理 → 中止启动
storage → 返回所有 TableMeta
core → 重建内存 Catalog（空库首个 TableId 为 0；非空库取已存在最大值之后继续分配）
```

### 关闭

```text
入口正常退出 → core.close_database
core → close_storage → storage
storage 完成统一落盘与资源释放
```

### 多语句批处理

```text
入口把整段文本交给 core
core → split_statements(文本) → SplitStatement 列表（sql + start）
core 循环：
  用当前 CatalogView 编译当前语句的 sql
  成功则执行并放入对应结果
  失败则停止：无部分副作用时放入 Error；
  INSERT/DELETE 部分成功时放入携带 error 的 CommandResult
  DDL 成功后更新 Catalog
  处理下一条语句
```

### CREATE TABLE

```text
core 分配 table_id
core → create_table(table_id, 表名, 列定义) → storage
storage 成功
core 更新 Catalog
```

### SELECT

```text
core → open_table(table_id) → cursor
循环：
  core → scan_next(cursor)
  storage → Record（全行）
  core 把 Record 转成内部 Row，执行 Filter / Project
core → close_cursor(cursor)
close_cursor 成功 → core 组装 QueryResult
close_cursor 失败 → 丢弃已收集行，返回该 Error
```

### DELETE

```text
open_table + 循环 scan_next
core 对每条 Row 求值 WHERE，收集命中的 RecordId
close_cursor
close_cursor 成功后 → core → delete_records(table_id, record_ids) → storage
close_cursor 失败 → 中止，不执行删除
```

## 10. 已确认决策汇总

| 决策 | 结论 |
|---|---|
| NULL | 后期可选，初版不支持 |
| 标识符 | ASCII `[A-Za-z][A-Za-z0-9_]*`，规范化后 `[a-z][a-z0-9_]*`，长度 1..64 |
| TableId | `0..UINT32_MAX` 均合法，0 无保留含义 |
| 类型系统 | `Type`/`Value` 一一对应：INT32、INT64、FLOAT、DOUBLE、BOOL、VARCHAR；Core SQL 先支持 INT32/VARCHAR |
| VARCHAR | 值必须为合法 UTF-8；字节数 ≤ 1024 |
| 大小上限 | 单行逻辑载荷 ≤ 4096（INT32/FLOAT 4、INT64/DOUBLE 8、BOOL 1、VARCHAR 按 UTF-8 字节数）；与物理编码无关；超限返回 kValueTooLarge |
| 分号规则 | 初版所有语句必须以 `;` 结束，无末条省略例外 |
| SQL 范围 | 初版仅 CREATE/INSERT/SELECT/DELETE；无 UPDATE/DROP/SHOW/ALTER 与列约束 |
| 分句 | compiler 提供无状态 split_statements，返回带 start 的 SplitStatement 列表；core 持有并循环编译执行 |
| 错误位置 | CompileError.location 相对单条语句；core 用 start 换算为整段输入绝对位置 |
| 行列计数 | 行按 `\n`；CRLF 算一个换行；列按 UTF-8 字节计，从 1 开始 |
| 批处理遇错 | 立即停止，返回已执行结果与该错误 |
| REPL 输入 | 初版按行提交，一行内可多条语句；跨行 SQL 为后期优先升级项 |
| storage 生命周期 | open_storage/close_storage；目录缺失时创建；数据目录缺省 ./tinydbms-data，可用 --data-dir 覆盖 |
| 持久化承诺 | 正常 close_storage 统一落盘后重启可见；排除显式 flush API、逐操作 fsync 与崩溃恢复 |
| ColumnId | 等于建表列序 0..n-1，不单独分配 |
| CatalogView | 借用式 `span<const TableMeta>` |
| 表达式 | compiler 编译期生成 Plan/Expr；core 运行期求值；storage 不参与 |
| 扫描 | 游标式全行返回，core 负责过滤与投影 |
| 错误优先级 | 扫描错误优先；扫描正常但 close_cursor 失败时 SELECT/DELETE 以该错误失败 |
| storage 校验 | 表/游标/行列数/类型/逻辑载荷/名称语法与 ID、表名唯一性由 storage 校验并分类报错 |
| 批量消息 | INSERT 一次多行；DELETE 一次一串 RecordId；失败即停并返回部分结果 |
| 部分失败表示 | INSERT/DELETE 部分成功时返回携带 error 的 CommandResult；无部分副作用时返回 Error |
| RecordId | storage 分配，对 core 不透明 |
| 用户输出 | QueryResult / CommandResult / Error；入口逐条展示 |
| StorageError | 顶层六类，细节由 storage 内部扩展 |
| 命名 | Record 只用于 storage 边界；core 内部行叫 Row；未来日志条目叫 LogEntry |
