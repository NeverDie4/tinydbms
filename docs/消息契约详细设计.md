# tinydbms 消息契约详细设计

本文是对 `include/tinydbms/*.hpp` 的说明。若与头文件不一致，以头文件为准。

## 公共基础类型

`tinydbms::TableId` 与 `ColumnId` 当前均为 `uint32_t` 别名。TableId 由 Core 分配；ColumnId 是 TableMeta 中列的零基序号。

`Type` 只有 `kInt` 和 `kVarchar`。`Value::data` 是 `variant<int32_t, string>`；`ColumnMeta` 为 `{name, type}`；`TableMeta` 为 `{table_id, table_name, columns}`，columns 顺序就是记录布局。

## Compiler

`compiler::CatalogView` 在一次编译调用中借用 Core catalog。`compile(CompileRequest)` 返回 `Plan` 或带相对语句位置的 `CompileError`；Core 将其换算为整段 script 的绝对位置。

Plan variant 包含：

- `CreateTablePlan { table_name, columns }`：尚无 TableId，由 Core 分配。
- `InsertPlan { table_id, columns, rows }`：`columns` 为空表示 schema 顺序；非空时必须是全列的完整排列。
- `DeletePlan { table_id, optional<Expr> predicate }`。
- `QueryPlan { root }`：当前真实形状为 `ProjectNode → optional FilterNode → SeqScanNode`。

表达式节点是 `ColumnRef { column_id }`、`Literal { value }`、`Binary { CmpOp 或 LogicOp, lhs, rhs }`、`Unary { kNot, operand }`。初版 comparison 支持 INT 的六种比较和 VARCHAR 的 `=`/`!=`，并由 Compiler 完成类型检查。

## Storage

所有 Storage API 位于 `tinydbms::storage`：

| 请求/结果 | 含义 |
|---|---|
| `open_storage(OpenStorageRequest)` / `close_storage(CloseStorageRequest)` | 打开或关闭 singleton Storage |
| `list_tables(ListTablesRequest)` | 返回持久化 schema snapshot |
| `create_table(CreateTableRequest)` | Core 提供 TableId，Storage 验证并持久化 |
| `open_table(OpenTableRequest)` | 成功返回 `OpenTableResult.cursor` |
| `scan_next(ScanNextRequest)` | `record` 空且 `error` 空表示 EOF |
| `close_cursor(CloseCursorRequest)` | 返回 `CloseCursorResult` |
| `insert(InsertRequest)` | 全行 schema order；成功前缀写入 `InsertResult.rids` |
| `delete_records(DeleteRequest)` | 接收 `DeleteRequest.rids`，返回 `deleted_count` |

`Record` 是 `{ rid, values }`；RID 由 Storage 分配，Core 只能保存和原样传回。`CursorId` 也属于 `tinydbms::storage`。Storage 错误是 `StorageError { kind, message }`，kind 为 `kTableNotFound`、`kCursorInvalid`、`kValueTooLarge`、`kIoError`、`kCorrupt` 或 `kInvalidRequest`。

Cursor 在同表存在时阻止非空 mutation。因此 SELECT 的扫描路径必须关闭 cursor；DELETE 必须先收集 RID、关闭 cursor，再调用 `delete_records`。EOF 不产生 Record，也不表示错误。

## Core

Core 的公开对象是 `core::Database`：

```cpp
OpenDatabaseResult open(const OpenDatabaseRequest&);
CloseDatabaseResult close();
ExecuteScriptResult execute_script(const ExecuteScriptRequest&);
```

`OpenDatabaseRequest.data_dir` 为空时使用 `./tinydbms-data`。Database 维护 lifecycle、Storage owner、catalog snapshot 和 TableId allocator；多个对象可创建，但同一进程只能有一个 open 或 cleanup-pending owner。

`ExecuteScriptResult.outcomes` 以 statement 顺序保存已尝试结果，遇到 Error 或带 error 的 CommandResult 后停止。每个 `ExecuteResult` 是以下之一：

- `QueryResult { columns, rows }`：columns 是 `{name, type}`，rows 是 `vector<Value>`。
- `CommandResult { affected_rows, optional<Error> error }`：CREATE 成功时 affected_rows 为 0；INSERT/DELETE 部分成功时保留成功前缀计数和 error。
- `Error { ErrorKind, optional<SourceLocation>, message }`：`kCompile`、`kExecute`、`kStorage`、`kInternal`。

Core 的 query executor 在 Storage 完整行上计算 predicate，最后按 Project ColumnId 构造 QueryResult。任何 scan、expr、projection 或 close-cursor 错误都不发布部分成功 QueryResult。
