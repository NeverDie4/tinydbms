# tinydbms 模块交互契约

本文记录已确认的模块职责与交互方向；字段级消息契约见 [docs/消息契约详细设计.md](消息契约详细设计.md)。

## 1. 模块形态与职责

- 单进程，无 IPC、网络或消息总线。
- 三个静态库：`tinydbms_compiler`、`tinydbms_storage`、`tinydbms_core`，外加一个可执行入口。
- core 拥有逻辑 Catalog（表名/ID 映射、列定义），并负责执行协调。
- compiler 无状态，对外提供 `split_statements` 与编译入口，调用完即忘；其内部流水线不规定，由该模块实现者决定。
- storage 拥有全部物理存储逻辑（页、缓冲、文件、记录布局），并持久化物理元数据。
- storage 通过 open_storage/close_storage 管理生命周期；数据目录来自 core 传入的 data_dir。
- close_storage 一旦被调用即释放打开状态；返回错误只表示落盘/收尾未完整成功。
- storage 不提供文件锁；初版不支持两个进程同时打开同一 data_dir。
- open_storage 在目录缺失时创建；目录非空但缺少合法 storage 元数据时返回 `kCorrupt`，不覆盖已有文件。
- data_dir 存在但不是目录或不可访问时返回 `kIoError`；空目录视为新建数据库。
- data_dir 跨平台统一使用 UTF-8 字符串；Windows 入口负责把宽字符路径转换为 UTF-8。
- storage 成功返回表示操作已更新内部状态，正常 close_storage 后重启可见；不承诺逐次 fsync 或崩溃恢复。
- storage 校验表存在性、cursor、行列数、Value 类型、逻辑载荷上限与 RecordId 归属，错误按 StorageErrorKind 分类返回。
- storage 生命周期非法调用返回 `kInvalidRequest`：重复 open、未打开时调用其他 API、重复 close；
  空 `DeleteRequest.rids` 是成功的零行删除，已结束但未关闭的 cursor 可重复返回扫描结束，关闭后再使用返回 `kCursorInvalid`。
- `data_dir` 空字符串非法；“空目录”仅指已存在且没有条目的目录。
- storage 普通失败通过 Result 返回；core 不允许 storage 异常越过公开 Database API，析构与移动赋值的兜底清理必须捕获异常。
- 本文只规定模块边界，不规定 compiler 与 storage 的内部实现方案。

## 2. 可执行入口 ↔ core

- 产品形态为一个可执行文件。
- 默认交互式 REPL，同时支持 stdin 批处理。
- REPL 初版按行提交，一行内可包含多条完整语句；跨行 SQL 为后期优先升级项，初版不实现。
- REPL 以 EOF 退出（Unix 终端通常 Ctrl-D；Windows 控制台通常 Ctrl-Z 后回车），初版不提供 SQL 之外的元命令。
- 入口支持可选 `--data-dir <DIR>`，缺省使用当前目录下的 `tinydbms-data/`。
- core 对入口暴露有状态 `Database` 对象（open/close/execute_script），不是自由函数。
- 入口创建 Database 对象并调用 open，正常退出前调用 close。
- Database 可移动、不可复制；close() 返回 Error 后不再处于打开状态；
  析构时若仍打开，core 做 noexcept 的 best-effort 兜底关闭。
- moved-from Database 上的公开方法均返回 `ErrorKind::kExecute`，析构必须安全。
- storage API 初版为无句柄单例：同一进程同一时间只能打开一个数据库；
  第二个 Database::open 返回 Error，不影响已打开实例；storage 句柄化列为后续扩展。
- 入口只负责读入 SQL、展示 core 返回的结果与错误，不包含任何业务逻辑。
- core 返回结构化结果，展示排版由入口负责。
- CLI 参数错误（未知参数、缺少 `--data-dir` 值、重复 `--data-dir` 或空值）返回退出码 2；
  批处理 SQL/运行时错误和 REPL 期间发生过的 SQL/运行时错误返回退出码 1。
- 批处理遇错后 core 停止剩余语句；REPL 展示当前错误后继续下一行，EOF 后 close，最终按累计错误标记决定退出码。

## 3. core ↔ compiler

- core 发起编译请求：SQL 文本 + 只读 CatalogView。
- compiler 返回 CompileResult：LogicalPlan 或 CompileError；CompileError.location 相对单条语句文本。
- compiler 对外提供无状态 `split_statements`：整段文本拆成带起点 start 的 SplitStatement 列表，列表由 core 持有。
- core 用 SplitStatement.start 把 CompileError 的相对位置换算成整段输入的绝对位置后再对外展示。
- core 循环执行“取一条 → 编译一条 → 执行一条”；DDL 成功后立即更新 Catalog，不能整段预编译。
- 可执行入口只把整段文本交给 core，不负责拆句，也不解析 SQL。
- compiler 内部如何实现（词法、语法、语义、优化）不跨模块，不在此规定。
- LogicalPlan 中引用已有表/列时使用 ID；CatalogView 提供名字与 ID 的映射。
- CREATE TABLE 属于例外：新表尚无 ID，Plan 携带表名与列定义；ID 由 core 在执行时分配。
- 编译失败时，core 不产生任何存储副作用。
- compiler 生成的合法 InsertPlan 必须至少包含一行；columns 非空时必须是全列 ColumnId 的无重复排列。
- compiler 生成的合法 QueryPlan 只能是 `SeqScan`、`Filter -> SeqScan`、`Project -> SeqScan` 或
  `Project -> Filter -> SeqScan`；Project 位于 Filter 外层，Project outputs 非空，重复列按原顺序保留。
- compiler 必须完成 Expr 的静态类型检查；core 在调用 storage 前仍须重复校验 Plan/Expr 不变量，
  以防 fake 或异常 compiler 产生非法 Plan。

## 4. core ↔ storage

### 已确认原则

- 接口为类型化行：core 传递列值集合，storage 负责记录布局与编码解码。
- storage 认识表结构（列顺序、类型、布局），用于编码记录与持久化元数据。
- 逻辑 Catalog（名字与 ID 的映射、语义查询）归 core；storage 不实现该语义职责。
- 物理存储逻辑（页、Buffer Pool、文件、记录布局）只归 storage。
- 表结构持久化在 storage 控制的固定元数据区；core 启动时通过 storage 恢复 Catalog。
- 持久化承诺限于正常关闭后重启可见；不包含进程崩溃或断电场景。
- storage 负责基本校验：表不存在、cursor 非法、行列数/类型/逻辑载荷超限均分类报错。
- TableId 由 core 分配；ColumnId 等于建表列序 0..n-1，不单独分配。
- storage 不认识 SQL、WHERE 或表达式；删除操作按 RecordId 进行。
- core 只有在 Plan、表达式和列头预校验成功后才调用 storage 的表、游标和写入接口；预校验失败
  不产生 storage 副作用。
- core 对 OpenTableResult/ScanNextResult 做组合校验。非法组合返回 `kInternal`；如果非法结果
  携带 cursor，core 将其视为已取得并至多尝试一次 close。
- core 对每个已取得 cursor 使用一次性清理语义：close 调用前标记已尝试，close 返回错误或抛异常
  后不得由析构重复调用。

### 命名约定

- `Record` 只用于 storage 边界：RecordId + 全行列值。
- core 执行器内部处理的行叫 `Row`。
- `RecordId` 由 storage 分配，对 core 不透明。
- `Value` 是 core 与 storage 共享的类型。
- 未来恢复日志的条目叫 `LogEntry`，不与行记录混淆。

### 消息方向

```text
启动/关闭：open_storage / close_storage
启动恢复：list_tables
建表：    create_table
扫描：    open_table / scan_next / close_cursor
写入：    insert
删除：    delete_records
```

各消息的请求、结果与错误字段见字段级契约。

## 5. 用户可见输出

- SELECT 返回 QueryResult：列信息 + 行数据。
- INSERT / DELETE / CREATE 返回 CommandResult：成功状态与受影响行数。
- INSERT / DELETE 部分行成功后 storage 出错时，CommandResult 携带 error 与已成功行数；无部分副作用的失败返回 Error。
- 编译错误带错误种类、行列号与原因；对外展示时行列号为整段输入的绝对位置。
- 执行/存储错误带错误种类与原因，不带行列号。

## 6. 范围边界

本阶段单线程顺序执行，不包含事务与并发控制；也不包含崩溃恢复、显式 flush API 与逐操作 fsync。
正常 close_storage 时的统一落盘属于初版范围。
持久化承诺仅限“正常 close_storage 后重启可见”，不包含进程崩溃或断电场景。
未来涉及日志时使用 `LogEntry` 命名，并需要重新扩展契约。
