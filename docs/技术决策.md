# tinydbms 技术决策记录

状态说明：

- **已定**：已确认的技术基线，改动需要重新确认。
- **建议**：当前推荐，尚未最终拍板。
- **未决**：尚未开始确定；在确定前不按假设实现。

## 已定

### 1. C++20（保守子集）

全项目使用 C++20。CMake 固定：

```cmake
set(CMAKE_CXX_STANDARD 20)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_CXX_EXTENSIONS OFF)
```

不使用 ranges、coroutines、modules。不使用 GCC 专属扩展，以保证 MSVC 可编译。

### 2. 平台与编译器

- Linux 开发与构建使用 g++。
- Windows 开发与构建使用 MSVC。
- 同一份源码必须能被两边编译，任何一侧的编译器特性都不能成为前提。
- 本地编译器版本较高不作为使用更新语言特性的依据。

### 3. 构建工具

CMake 负责工程描述，Ninja 负责实际构建。构建、测试入口由 CMakePresets 固定。

### 4. 进程与模块形态

- 单进程，无 IPC、网络或消息总线。
- 三层静态库：`tinydbms_compiler`、`tinydbms_storage`、`tinydbms_core`。
- 一个可执行入口 `tinydbms`。

### 5. 测试

- CTest 作为测试运行入口。
- 现阶段自写断言，不引入第三方测试框架。
- GoogleTest 作为后期可选方案，引入前需要单独确认，并决定离线构建下的引入方式。

## 建议（尚未拍板）

### P1. 用户入口形态：CLI/REPL

建议采用命令行交互/批量 SQL 输入（`tinydbms < test.sql` 或逐行 REPL），不做 client-server。
理由是便于课程验收与隐藏测试、跨平台成本低，且未来如需网络形态可以在外层加适配器。

## 未决

- SQL 编译器层与页式存储层的内部技术方案未定，本文档不预设。
- 第三方运行时依赖策略未定。当前骨架不引入第三方依赖只是现状，不是已定策略。
- 用户入口形态最终选择未确认（见 P1）。
- 数据/文件格式、SQL 支持范围、事务/并发/恢复范围等均未定。
