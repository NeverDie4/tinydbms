## 1. 通知原则

- `include/tinydbms/` 是所有模块共享的正式接口；任何字段、variant、枚举、构造函数或错误语义变化都必须在修改前通知直接消费者。
- A 类决策已关闭，公共头文件尚未修改；收到 Compiler/Storage 确认前，不要求其他成员立刻适配代码。
- 通知应说明“类型形状、语义不变量、迁移窗口、测试要求”，不能只发一个头文件 diff。
- Compiler 内部实现不由 Core/CLI 成员指定；通知只陈述 Core 需要的输入/输出契约。
- 诊断/恢复线与 SQL v2 能力线分开发送和评审，避免把无 Storage 改动的首轮升级与磁盘格式升级混在一起。

## 2. 现在需要通知的成员与内容

### 2.1 Compiler 成员：契约已定稿，等待确认适配时间

以下条目已定稿，等待 Compiler 成员确认可在同一集成窗口完成适配：

- [x] 新增公共 `diagnostic.hpp`，其中定义 `SourceRange`、`FixIt`、`CompileStage`；范围采用半开区间，行列 1-based、UTF-8 字节偏移 0-based；换行规则继承现行契约（`\r\n` 计一个换行、`\r` 不占列、Tab 按字节），端点不得落在 `\r\n` 之间。
- [x] `CompileError` 携带 stage、语句相对范围、可选 suggestion 和单个 fix-it；每条语句最多一个主诊断和一个可选 fix-it（A8）。
- [x] `CompileErrorKind` 直接删除、统一改用 `CompileStage`；不保留别名或双接口（已确认无外部消费者）。
- [x] `SplitStatement` 从单一 start 升级为脚本绝对 SourceRange；`sql` 保留从语句首字符到结尾分号的原文（含前导空白/注释），`source` 与 `sql` 一一对应。
- [x] 分句失败只由 `kMaxSqlBytes` 和分句契约违反触发；**未闭合字符串/块注释仍作为残缺语句交给 `compile()` 报词法错误**；一旦分句失败则保守停止整个脚本，不做启发式恢复，脚本级错误使用空插入点 `{1,1,0}-{1,1,0}`。
- [x] Compiler 仍以单条 `compile()` 为基本入口；脚本聚合、执行门、语句数上限和影子 Catalog 都由 Core 负责，Compiler 不实现“语句列表 + 分句错误”的部分成功结果。
- [x] Compiler 无需按 Core 指定方式实现候选词、语法恢复或 AST；只需保证公开结果和范围满足契约。
- [x] Compiler 正常公共函数不得抛异常，低置信度建议可以省略。
- [x] `split_statements()` 的 `CompileError::source` 是整段脚本绝对范围，`compile()` 的 `source`/`fix_it.range` 是单条语句相对范围；两类坐标系不得混用。
- [ ] Compiler 成员确认字段、坐标系（含 CRLF/Tab/EOF 端点）、分句边界和适配时间点。
- [ ] 真实联调时间点：公共头文件落地且 Compiler 完成适配后，不由 Core/CLI 的 fake 代替验收。

**对 Compiler 的影响等级：高。** `CompileError` 和 `SplitStatement` 是源代码不兼容变更，必须在同一集成窗口修改实现和测试。

### 2.2 app/CLI 消费者：Core/CLI 组内必须同步

- [x] `ExecuteScriptResult` 从 outcomes 升级为逐语句 `StatementResult`，并增加 `script_error`；`ErrorKind` 增加 `kAnalysis`。
- [x] 新增 stop/analyze 策略（默认 stop）与七种语句状态：`kExecuted`、`kCompileError`、`kExecutionError`、`kExecutionIndeterminate`、`kAnalysisError`、`kAnalysisOnly`、`kSkippedExecution`。
- [x] `StatementResult` 只能经命名工厂构造，字段私有且只读访问；工厂校验状态与 outcome 组合。
- [x] 错误分为结构化错误（可继续分析）与致命中止（`script_error` + 剩余 `kSkippedExecution`）；`kInternal` 只出现在 `script_error`，执行器返回 `kInternal` 时按 `side_effects_possible` 决定 `kExecutionIndeterminate` 或 skipped。
- [x] 新增 `kMaxStatementsPerScript = 4096`，split 成功后、任何编译/执行前检查；超限时 statements 为空、`script_error` 为 `kCompile`/`kLex`，无 Storage 调用。
- [x] CLI stdout 只保留真实执行结果；诊断、suggestion、fix-it、ANALYZED、SKIPPED、INDETERMINATE 均进入 stderr；首轮不默认输出摘要。
- [x] analyze 后续成功不能输出 OK，也不能恢复 0 退出码；任何 `script_error` 都按 REPL 致命处理（停止读取 + best-effort close）。
- [x] app 私有 Session/FakeSession 和所有输出快照需同批迁移。

**影响等级：高，但属于本组。** 不能只改 Core 后让 CLI 通过解析 message 临时兼容。
